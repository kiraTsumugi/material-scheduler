# 01 · 需求

## 用户与目标

**用户**：内容团队的运营/审核人员。
**目标**：为一批待发布素材快速得到「无冲突、可确认」的发布排期**草稿**，把"哪些素材能发、什么时段发、有哪些风险/待确认项"一次性说清楚。

**非目标**：真实发布、排期最终生效、自动改用户的硬性要求。

## 范围

| 做 | 不做 |
|---|---|
| 读素材元数据、查审核规则、查时段、存草稿 | 真实发布接口 |
| 冲突消解（软要求建议替代时段） | 擅自更改硬性发布时间要求 |
| 幂等防重复保存 | 多用户并发协调 |
| 步数上限与未完成状态 | 生产级持久化/调度 |

## 输入

- 素材 ID + 元数据（`data/materials.json`，合成）
- 发布要求：`publish_requirement {time, level: hard|soft}`
- 已有排期与占用（`data/schedule.json`）
- 审核规则（`data/rules.json`）

## 成功标准（对应考核验收点）

| # | 成功标准 | 判据 |
|---|---|---|
| S1 | 正常排期 | 空闲时段 → 草稿保存成功 |
| S2 | 素材信息缺失 | 缺字段 → 请求补充，不阻断也不保存 |
| S3 | 规则风险 | block 级违规 → 阻断 |
| S4 | 时段冲突 | soft → 建议替代 + 待确认；hard → 请求确认，不改时段 |
| S5 | 重复提交 | 相同请求只产生一份草稿 |
| S6 | 保存失败 | 明确返回失败，不虚报成功 |
| S7 | ReAct 决策 | 模型据工具事实调整动作，≥2 条不同路径 |
| S8 | 步数上限 | 超限返回 `incomplete` |
| S9 | 边界 | 绝不称「已发布」；未经同意不改硬性要求 |

## 交付结果字段

每项素材输出：`审核状态` / `风险原因` / `建议时段` / `待确认项` / `草稿保存状态`。
